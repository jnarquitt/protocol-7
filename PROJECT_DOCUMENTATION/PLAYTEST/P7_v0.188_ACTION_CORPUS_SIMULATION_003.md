# Protocol 7 v0.188 — Persona / Action Checklist Simulation 003

**Plain-language purpose:** run a defined set of people and situations through the rules to find gaps, then re-check established behavior so new work does not break old work (regression testing).

**Verification level:** rules/source and app-structure simulation. Not an interactive browser test.

## Personas and scenes

### Maya — first-time player: alley ambush
Maya's Vector is escorting an NPC when a hidden shooter attacks. Tested: noticing danger, surprise, taking cover, defending the NPC, returning fire, physical-dice pool identification.

Result: surprise needed a clear explanation without a special surprise round. Interception needed a rule. Cover already had a mapping. New rules use ordinary Advantage/Disadvantage and Reaction rather than introducing another subsystem.

Learning-design finding: PLAY should eventually phrase the choice as an intention ('Protect ally', 'Take cover') before exposing the technical rule name. This supports recognition over recall.

### Derek — tactical player: four attackers in a warehouse
Tested: multiple attackers, Reaction availability, interception, cover + armor, repeated attacks, coordinated enemies.

Result: no automatic multi-attacker penalty. Existing action economy already creates pressure. Coordinated positioning can create Advantage/Disadvantage. Interception consumes Reaction and redirects the attack; it is not a free counterattack.

Exploit check: unlimited interception is prevented by one-Reaction economy. Multiple helpers still cap at one effective Assist. Cover does not become a Gear die, so armor + cover retain separate named sources.

### Marcus — mounted pursuit, 1241
Tested: quarry flees on horseback through broken terrain, pursuer chooses direct route, both fire bows during chase, quarry tries to escape.

Result: Riding and Archery now separate control from weapon competence. A simple Lead track (-3 to +3) gives pursuit scenes a beginning/end without inventing speed arithmetic for every historical mount. Powerful/Overwhelming margin shifts Lead two steps, rewarding strong rolls using existing margin language.

### Lena — 1970 vehicle surveillance pursuit
Tested: tail becomes chase, route knowledge, driving, creating separation, losing pursuers.

Result: same chase structure works with Driving. Tradecraft can establish position before the chase; once relative movement is the contest, Driving becomes primary. This supports cross-era reuse.

### Priya — chase edge cases
Tested: superior vehicle, clever shortcut, Gear/VAM support, ties, repeated large margins.

Result: existing Advantage/Disadvantage and Skill-selection rules are sufficient for most situational differences. No extra 'chase die' needed. Exact tie handling should remain ordinary opposed-roll handling; if the underlying opposed rule needs explicit tie wording later, fix it globally rather than only in chases.

### Alex — physical dice
Tested whether new procedures require digital-only calculations.

Result: Lead is a simple integer track and all checks use normal pools, so physical dice remain fully viable.

### Jordan — mobile
Tested conceptual interaction load.

Result: a future PLAY implementation should use a compact Chase card with large +/− Lead controls and intent buttons, not text entry. Hazard guidance should be contextual reference, not permanent screen clutter.

## Hazard scenarios

Tested fall from rooftop, smoke/fire escape, underwater escape, poison, sudden electrical hazard, explosion behind cover, cold exposure.

Finding: existing Reflex/Fortitude/Survival + Difficulty system covers the checks, but consequences cannot responsibly be reduced to one universal damage number without play evidence. r006 deliberately keeps severity judgment-based. This is an explicit playtest question, not an accidental missing rule.

## Changes accepted this pass
- Chase Lead track from -3 to +3 using opposed existing Skills.
- Powerful/Overwhelming chase win shifts Lead two steps.
- Reaction interception to defend another reachable character.
- Surprise/ambush uses fiction + Advantage/Disadvantage; no separate surprise round.
- No automatic multiple-attacker penalty.
- Hazard mapping clarified without premature universal damage tables.
