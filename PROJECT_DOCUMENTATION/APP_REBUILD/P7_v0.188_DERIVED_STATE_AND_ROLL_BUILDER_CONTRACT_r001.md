# Protocol 7 v0.188 — Derived State & Roll Builder Contract r001

**Status:** GATE B DATA-MODEL AUTHORITY

## Derived state law

The character save stores only player choices and mutable play state. Mechanical values that can be calculated from those choices are derived at runtime from central rules data.

Do not persist competing copies of:
- current Ability die after advancement;
- current Skill dice from ranks;
- starting HP;
- maximum HP;
- BAR ceiling;
- authorization band;
- available Edge/Ability-growth/Mastery slots;
- loaded BAR total;
- whether a VAM is authorized;
- Mastery Die size.

These values may be cached in memory for performance, but the cache is disposable and must never become independent authority.

## Required selectors / derivations

### Current Ability die
Input: base Ability die + number of legal Core Growth selections targeting that Ability at or below current Level.

Step along d4→d6→d8→d10→d12. Never exceed d12.

### Current Skill dice
Input: persisted Skill ranks + central breakpoint table.

Return the highest breakpoint whose required ranks do not exceed current ranks.

### Vitality validation
Each Vitality face must be legal for the **assigned starting Ability die used during the ritual**, not a later advanced die.

### Starting HP
If all six legal Vitality faces are 1–3: 28.
Otherwise: 18 + highest face.

### Maximum HP
Starting HP + 4 × (Level−1) + 5 if Durable Edge is selected and Level ≥2.

### BAR ceiling / authorization
Derived entirely from current Level using central Level rules data.

### Loaded BAR
Sum `bar_cost` for all loaded VAM IDs resolved from the canonical VAM catalog.

### VAM legality
A VAM is loadable only when:
- its authorization level ≤ current Level's authorization level;
- its prerequisites are satisfied;
- total loaded BAR after load ≤ current BAR ceiling.

### Mastery slots
0 at Levels 1–3; 1 at Levels 4–5; 2 at Level 6.

### Mastery Die
For the Skill being rolled, if that Skill is currently Mastered and a legal effect grants Mastery access, the Mastery Die equals that Skill's current Skill die expression. For multi-die Skill expressions, final Mastery behavior must follow synchronized Engine authority; until explicitly resolved, the functional skeleton must flag this case rather than invent a rule.

## Canonical roll-builder input

A roll request provides:
- roll purpose/type;
- Skill ID;
- associated Ability IDs selected/defined by the Skill rule;
- relevant gear candidates;
- relevant VAM/Feature candidates;
- Assist candidate, if any;
- Edge use candidate, if any;
- conditions/circumstance inputs;
- Mastery access candidates;
- exceptional explicit overrides.

## Canonical roll-builder output

Before randomization, return a complete explanation object:

- Skill dice;
- Ability dice with source labels;
- chosen ordinary Bonus Die and source;
- rejected competing ordinary bonus sources with reasons;
- Mastery Die and source if legal;
- gear contribution;
- Advantage/Disadvantage state as defined by synchronized Engine authority;
- final dice list;
- warnings/errors;
- human-readable explanation.

The random roller consumes exactly that final dice list.

## Ordinary bonus-source collision

Routine rolls permit at most one ordinary Bonus Die from ordinary Feature/VAM, Assist, gear/situation sources where those sources are classified as occupying that slot under final rules.

If multiple eligible sources exist, the system shall not silently stack or silently discard them. It returns a choice or deterministic rule plus a visible explanation.

## Result pipeline

1. Validate roll request.
2. Build labeled pool.
3. Present preview.
4. Roll exactly the previewed dice.
5. Score Protocol Dice.
6. Apply ordinary critical rules if/when synchronized.
7. Pass result through optional modular blank-pattern parser only when release authority enables it.
8. Return score, faces, margins/effects, labels, and rule explanations.

## Prohibited implementation patterns

- UI component directly computes its own pool.
- VAM behavior keyed only by displayed name.
- manually editable derived HP/BAR/Skill die.
- hidden flat numeric bonus inserted into result.
- Mastery Die appended because Skill is Mastered without checking access permission.
- roll preview that differs from dice actually rolled.
