# Protocol 7 v0.188 — Application Requirements Bible r002

**Status:** IMPLEMENTATION AUTHORITY — AUDITOR-RECONCILED FAST-TRACK EDITION
**Date:** 2026-08-25

## Mission
Build the Protocol 7 v0.188 Interactive Character & Play App as a clean implementation using one authoritative character state and one authoritative roll builder. Reuse the successful visual/product organization of v0.187, but no predecessor mechanical behavior is authoritative merely because it exists.

## Architectural law
- Exactly one persisted character-state object.
- Exactly one roll builder for all player-facing rolls.
- Derived values remain derived, never competing manual state.
- Rules/catalog data is separated from UI code.
- Saves record schema and rules version; v0.187 saves are never silently treated as valid v0.188 characters.
- No hidden flat numeric modifiers.
- No generic bonus-die slot.
- Every die added or removed from a pool must have a named legal source.

## Touch-first product law
The app is phone-portrait first. Except for the Vector's name, normal character creation and play must not require typing. Abilities, Skills, advancement, VAMs, Gear, conditions, HP/AP controls, presets, and other ordinary mechanical choices use buttons, selectors, cards, toggles, steppers, plus/minus controls, or similarly large touch targets. Aim for approximately 44 CSS px minimum primary touch dimension. No gameplay function depends on hover, fine gestures, or horizontal page scrolling.

Primary navigation: Character • Skills • VAMs • Gear • Play • Advancement. Rules are a link to the Interactive Rules Guide, not a primary app tab. Persistent bottom navigation or equivalent is required on phones.

## Character creation
Offer Preconfigured Vector and Custom Vector. Custom creation enforces d8, d8, d6, d6, d4, d4 across STR/DEX/CON/INT/WIS/CHA; 20 starting Skill Ranks; Level 1 BAR 16; and legal Level 1 authorization. Unused BAR is legal.

### Vitality Ritual
The app deliberately rolls/records each Ability in order: STR, DEX, CON, INT, WIS, CHA. Each face must be valid for that Ability die. Faces 1–3 are blanks. If any face is 4+, starting HP = 18 + the highest face. If all six are blanks, starting HP = 28. On a tie for highest qualifying face, the player selects one tied Ability as Vitality Origin. Vitality Origin is interpretive, not another modifier. Later maximum HP = starting HP +4 per Level after Level 1 +5 if Durable is selected.

## Skills and advancement
Skill ranks map to dice: 0=d4; 1–2=d6; 3–5=d8; 6–9=d10; 10+=d12. d12 is the ordinary Skill ceiling. Level range is 1–6. Every Level after 1 grants +4 maximum HP and +4 Skill Ranks. Level 2 grants one Edge; Level 3 one Ability step; Level 4 first Mastered Skill; Level 5 second Ability step; Level 6 second Mastered Skill. Ability ladder is d4→d6→d8→d10→d12, capped at d12. Advancement is reversible for playtest correction but must warn before invalidating dependent choices.

## Edges
Driven: once/session, after rolling reroll one die and keep new result. Inspired: once/session, before rolling grants Advantage; it is NOT an ordinary bonus-die slot. Prepared and Connected expose once/session usage plus concise fictional permission reminders. Durable permanently adds +5 maximum HP.

## VAM and BAR
BAR ceilings by Level: 16/18/21/24/27/30. Catalog is the v0.188 VAM canonical database. Selector enforces authorization and BAR. Loading into unused BAR is free. Replacing/unloading already-loaded VAMs during active play costs 1 AP for the entire field swap, not per VAM. Out-of-play configuration does not charge AP. BAR meter updates immediately. Presets are convenience loadouts, not classes, and remain editable.

## Skill Mastery
Level 4 grants one Mastered Skill; Level 6 grants a second. A Mastered Skill's Mastery die equals its current Skill die but is dormant without explicit legal Mastery access. Only the currently rolled Skill's Mastery die can enter its pool; maximum one Mastery die per roll. The roll builder labels it explicitly.

## Canonical roll builder
Ordinary core pool = one Skill die + that Skill's three associated Ability dice. Repeated Abilities are intentional and produce repeated dice.

Optional named sources are separate:
- one primary relevant Gear die normally;
- VAM dice only when explicit VAM text permits them;
- Advantage/Disadvantage through the universal A/D rule;
- one Mastery die when both Mastered Skill and explicit Mastery access apply.

There is no generic bonus-die slot and no routine flat +1/+2 modifier channel. Before rolling, show every component with source label. The displayed dice must be the dice actually rolled. Illegal competing sources are explained rather than silently altered.

### Advantage / Disadvantage
Advantage adds one d6. Disadvantage removes the smallest Ability die. Reasons cancel one-for-one; after cancellation a remaining side applies once. Multiple same-side reasons do not normally stack without an explicit rule. The GM can award situational A/D; explicit rules can trigger it automatically. Players are encouraged to use tactics, preparation, positioning, knowledge, teamwork, and resources to earn Advantage.

## Play screen
Optimize for repeated table use. Keep current/max HP, AP, Reaction, BAR, conditions, and common rolls/actions readily visible.

### Action economy and movement
Maximum 3 AP per turn. An ordinary attack costs 1 AP. Movement costs 1 AP per 30 feet and may be repeated: 1 AP=30 ft, 2 AP=60 ft, 3 AP=90 ft. There is NO universal Run action and NO double-movement multiplier.

### Reaction
Normally one Reaction between turns. Banked AP from the current turn pays first. If no banked AP remains, the Vector may borrow at most 1 AP from the next turn. Unused banked AP expires when the next turn begins.

### Combat
Use active defense. A successful attack requires attacker total > defender total. Normal damage equals attacker total − defender total. Relevant armor normally contributes its Gear die to active defense and does not then reduce damage again. There is no universal v0.188 critical-hit subsystem.

## Gear
Use `P7_v0.188_GEAR_CANONICAL_DATABASE_r001.json`. Gear is concrete fictional capability and is not Advantage. Normally at most one primary relevant Gear die enters a roll. Weapons do not add a separate universal damage die. Gear without a sensible dice contribution may legitimately have no Gear die. Catalog balance is a playtest concern, not an implementation excuse to invent mechanics.

## Conditions
Use the v0.188 Condition canonical registry. Conditions that create Disadvantage feed the universal A/D system; they do not create independent penalty-die logic.

## Persistence and recovery
Autosave locally without an account. Provide export/backup before public promotion. Import validates schema/rules version. Never silently migrate incompatible predecessor mechanics. Reset/delete actions require explicit confirmation explaining what will be lost.

## Visual canon
Dark Protocol 7 presentation; red/black foundation with restrained dark-gold/yellow emphasis; high contrast; heavier headings; card grouping; prominent physical-looking dice; readable HP/BAR/AP meters; no decorative clutter behind functional controls. State changes must be obvious without excessive animation.

## Fast-track acceptance gate
The app is ready for v0.188 playtest promotion when:
- Level 1 custom creation can be completed touch-first with only Vector name typed;
- a preconfigured Vector can be loaded and edited;
- Vitality Ritual calculates legal starting HP;
- Skills enforce rank budget and d12 ceiling;
- VAM selector enforces BAR/authorization and field-swap cost;
- Gear can be selected without typing and enters rolls only as allowed;
- roll builder visibly and correctly resolves Skill + 3 Abilities + named legal sources;
- A/D, Mastery, active defense, damage, movement, AP, Reaction, and conditions match current authority;
- save/export/import work without silently accepting incompatible v0.187 state;
- phone portrait has no required horizontal scrolling and no tiny sole-action controls;
- Auditor finds no known predecessor-rule resurrection.

## Change-control instruction
Until v0.188 is published, implementation follows this document plus the current v0.188 Playtest Rules Source and canonical registries. If predecessor code conflicts, predecessor code loses. Do not reopen coherent systems for polish; log non-blocking balance concerns for actual playtest.
