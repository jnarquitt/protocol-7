# Protocol 7 v0.188 — Skill Progression Data Authority r001

**Status:** GATE B AUTHORITY
**Date:** 2026-08-23

## Source resolution

The v0.187 canonical structured rules source explicitly defines the Skill Rank breakpoints used by Protocol 7:

| Ranks | Skill dice |
|---:|---|
| 0 | d4 |
| 1 | d6 |
| 3 | d8 |
| 6 | d10 |
| 10 | d12 |
| 15 | d12 + d4 |
| 21 | d12 + d6 |
| 28 | d12 + d8 |
| 36 | d12 + d10 |
| 45 | d12 + d12 |

Ranks between these thresholds are **Progress Ranks**. They count toward the next breakpoint but do not alter the current Skill dice until that breakpoint is reached.

## App implementation rule

The v0.188 application shall persist **Skill Ranks**, not a manually editable Skill die result.

Current Skill dice are derived from the rank table above.

This closes APPREQ-001 from the Application Requirements Continuity Audit.

## Derivation examples

- 0 ranks → d4
- 2 ranks → d6, with 1 Progress Rank toward d8
- 5 ranks → d8, with 2 Progress Ranks toward d10
- 14 ranks → d12, with 4 Progress Ranks toward d12+d4
- 20 ranks → d12+d4, with 5 Progress Ranks toward d12+d6

## Data-law consequence

No UI component may independently store or override a Skill's current die string. The interface may display the current derived dice and progress-to-next-breakpoint, but ranks are the canonical character state.

If the Protocol Dice Engine later changes the rank table through explicit authority, the application updates the central rules-data table and all derived Skill displays/rolls change from that one source.
