# Protocol 7 v0.188 — Application Screen & Interaction Map r001

**Status:** PRE-IMPLEMENTATION UX AUTHORITY — subordinate to Application Requirements Bible

## Persistent shell

Every primary screen shares:
- Protocol 7 title/version state;
- current character name;
- current Level;
- compact HP / AP / BAR status where space permits;
- persistent primary navigation;
- Interactive Guide link;
- Protocol 7 Home control;
- save-state indicator only if meaningful and unobtrusive.

On phone portrait, primary navigation becomes a persistent bottom navigation pattern or equivalent large-touch control. No hamburger-only navigation for primary play screens.

## Character

Purpose: identity, creation, core Abilities, Vitality, and high-level character summary.

Sections:
- New / Load / Import / Export;
- Preconfigured vs Custom creation choice;
- identity/concept;
- six Ability dice;
- Vitality Ritual during creation;
- current HP/max HP summary;
- Level/Edge/Mastery summary after creation;
- concise advancement status with link to Advancement.

Creation mode may use a guided sequence, but the completed Character screen should not remain a wizard.

## Skills

Purpose: fast understanding and editing of learned competence.

Use internal sub-tabs or segmented controls:
- General
- Combat
- Defense

Each Skill row/card should show:
- Skill name;
- current Skill die/rank;
- its current three Ability dice;
- Mastered indicator if applicable;
- concise notes/permissions;
- Roll action where useful.

Avoid one giant undifferentiated scrolling Skill list.

## VAMs

Purpose: browse, understand, load, and reconfigure VAMs.

Top area:
- live BAR meter: used / ceiling;
- current authorization;
- active loadout name if any;
- Field Swap control/state during play.

Catalog controls:
- search;
- family filter;
- authorization filter/status;
- loaded-only filter;
- presets/loadouts.

Each VAM card:
- name;
- family;
- BAR cost;
- authorization;
- concise rule;
- Mastery tag where applicable;
- load/unload control;
- clear locked reason if unavailable.

Preset selection must visibly preview BAR before confirmation when useful and immediately update the meter when loaded.

## Gear

Purpose: equipment, weapons, period resources, and effect data.

Prioritize equipped/current gear over full inventory. Weapons/effects should expose the dice and tags used by the roll builder rather than forcing the player to remember them.

## Play

Purpose: primary session dashboard.

Above the fold / first viewport priority:
- current HP/max HP;
- AP remaining;
- Reaction available/used;
- BAR used/ceiling;
- important current conditions;
- common roll/action launcher.

Common actions should include obvious controls for attacks, defense, frequently used Skills, Running, VAM field swap, and Edge use where applicable.

Roll preview must show labeled dice sources before Roll is committed.

Result display must make the scored outcome quickly readable and reserve a clearly defined area for any later-authorized blank-pattern rule.

## Advancement

Purpose: understand what the current Level grants and make legal advancement choices.

Show a vertical Level 1–6 progression with current/completed/upcoming states.

Current Level card explains:
- +4 HP / +4 Skill Ranks where applicable;
- BAR ceiling and authorization;
- Edge / Ability growth / Mastery choice for that Level.

Editing an earlier advancement choice triggers dependency validation before committing the change.

## Rules Guide relationship

Do not recreate a full Rules tab. Contextual help links should deep-link to the Interactive Guide where practical. The app itself carries only the concise rule text needed to make the immediate decision.

## Home relationship

Every primary screen can reach Protocol 7 Home. Protocol 7 Home can reach Jade Lion Studios. The user should never have to use browser Back as the intended product-navigation model.
