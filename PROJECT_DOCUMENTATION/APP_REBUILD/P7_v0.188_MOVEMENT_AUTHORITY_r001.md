# Protocol 7 v0.188 — Movement Authority r001

**Status:** ACTIVE MECHANICAL AUTHORITY / GUARDRAIL
**Date:** 2026-08-23

## Canonical rule

A Vector may spend Action Points on movement. **Each AP spent on movement permits 30 feet of movement.** Movement is repeatable while AP remain.

- 1 AP spent on movement = up to 30 feet.
- 2 AP spent on movement = up to 60 feet total.
- 3 AP spent on movement = up to 90 feet total.

There is **no universal Run action**. There is no rule that requires all 3 AP to move quickly, and there is no universal ×2 movement multiplier.

A player may mix movement with other AP-costing actions as the action economy permits. Example: move 30 feet for 1 AP, take a 1-AP action, then move another 30 feet for the remaining AP.

## Prohibited stale rule

The following wording/behavior is obsolete and must not appear as current v0.188 mechanics:

- “Running costs all 3 AP.”
- “Run = 3 AP.”
- “Run allows double movement.”
- `run_ap_cost: 3`
- `run_move_multiplier: 2`
- any dedicated universal Run button that spends all AP and applies a multiplier.

## Provenance

This rule preserves the movement structure identified in the v0.187 Current State Snapshot: **30-foot repeatable Moves with no universal Run**. The v0.188 rebuild accidentally reintroduced an older Run rule into candidate canonical data. That reintroduction is a continuity defect, not an authorized mechanical change.

## Implementation requirement

The app should expose movement as a touch-first AP choice. The useful interaction is not a Run button; it is a movement control that makes the AP-to-distance relationship immediately visible, such as:

- MOVE 30 FT · 1 AP
- MOVE 60 FT · 2 AP
- MOVE 90 FT · 3 AP

The interface must respect current AP availability and must not imply that a character has to commit all AP to movement.

## Audit requirement

Before any v0.188 build is promoted, repository search and executable testing must establish that current authorities and player-facing v0.188 surfaces contain no active universal Run rule. Historical files may retain old wording only when clearly historical and non-authoritative.
