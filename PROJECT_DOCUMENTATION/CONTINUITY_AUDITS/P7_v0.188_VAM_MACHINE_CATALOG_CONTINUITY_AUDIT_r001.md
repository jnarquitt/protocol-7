## Findings

### VAMDATA-001 — MAJOR — Human-readable catalog uses superseded “ordinary Bonus Die” terminology
Several human-readable VAM rules were written before the later dice-source decision. Threat Focus, Counter-Ambush, Crossfire Geometry, Combat Synthesis, Cover Protocol, Motion Prediction, Behavioral Baseline, Trauma Orchestration, Command Link, Coordination Mesh, Distributed Command, Continuance Mesh, and similar entries still refer to an “ordinary Bonus Die.”

The later v0.188 dice-source decision explicitly abolishes the generic ordinary Bonus Die slot. The machine data therefore encodes these effects as explicit **VAM dice**.

**Consequence:** If the human catalog is left unchanged, a rules reader and the application can use different terminology and potentially infer different stacking behavior.

**Required disposition:** Rewrite affected human VAM entries to say the VAM itself adds the stated die. Do not reintroduce a generic slot. Then recheck machine data against the revised prose.

**Status:** OPEN.

### VAMDATA-002 — MINOR — Advantage/Disadvantage die count remains outside this catalog
The catalog correctly treats Advantage/Disadvantage as a separate mechanism, but this audit does not establish the exact add/remove quantity or cancellation behavior. Those rules must come from the synchronized core rules authority rather than being invented inside VAM data.

**Status:** OPEN but does not block VAM catalog structure.

### VAMDATA-003 — MINOR — Inspired Edge changed category
The prior candidate Inspired Edge added d4 through the now-retired bonus-die channel. Core rules data now records Inspired as a once-per-session **grant Advantage** effect instead.

**Consequence:** Advancement prose and acceptance tests must be synchronized before public promotion.

**Status:** OPEN synchronization item.

### VAMDATA-004 — GREEN — Mastery access is explicit
All Level 4 Mastery VAMs and relevant Continuance effects are represented through explicit Mastery access/effects rather than generic added dice. This matches the v0.188 Skill cap at d12 and preserves Mastery as the veteran growth path.

### VAMDATA-005 — GREEN — No name-based code behavior is required
Each VAM now has a stable machine ID and explicit effect metadata. The future app can dispatch behavior by effect type rather than hard-coded comparisons such as `if name === "Threat Focus"`.

## Three most embarrassing contradictions if shipped now

1. Rulebook says “ordinary Bonus Die,” app says “VAM die,” and players reasonably ask whether the two stack.
2. Inspired still says “add d4” in one product while the new data model says it grants Advantage.
3. An implementation invents Advantage/Disadvantage behavior because the VAM files deliberately do not define that core rule.

## Promotion recommendation

Do **not** promote the catalog publicly yet.

Proceed with the app architecture using the machine-data source classes, but before declaring Gate B fully GREEN:

1. synchronize the human-readable VAM catalog to explicit VAM-die wording;
2. synchronize Inspired Edge prose;
3. establish the exact Advantage/Disadvantage core rule in v0.188 authority;
4. re-run the catalog wording/data comparison.

The data architecture itself is approved for continued implementation.
