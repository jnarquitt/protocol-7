## Important normalization decision

The prior human-readable candidate catalog predates the latest v0.188 dice-source ruling and repeatedly calls some VAM-granted d4/d6 effects an `ordinary Bonus Die`. The database intentionally does **not** preserve that obsolete classification. It preserves the actual die, trigger, target, scope, and duration, but classifies the source as VAM.

This is a rules synchronization change, not a transcription error. The human-readable VAM catalog must be regenerated from this data/ruling before public v0.188 promotion.

## Remaining public-promotion blockers

1. The player-facing VAM prose still contains obsolete `ordinary Bonus Die` wording.
2. The app does not yet consume this database.
3. Advantage/Disadvantage final mechanical resolution must be represented in Engine authority before the roll builder can execute it.
4. Condition IDs such as Suppressed/Grapple need canonical condition objects rather than remaining descriptive references.
5. Skill IDs referenced by Mastery eligibility need the canonical Skill registry before strict foreign-key validation can be enabled.

## Chief Systems Architect finding

The database is suitable to become the sole VAM input for Gate C. UI code must never branch on VAM display names. It should interpret stable IDs plus effect operations. Human-readable descriptions should ultimately be generated from or audited against these records.

## Auditor finding

No VAM was silently deleted to accommodate the new architecture. All 84 approved slots remain represented. The main deliberate semantic normalization is the removal of the obsolete generic Bonus Die classification, consistent with the Creative Director's later v0.188 ruling.

## Next required work

Proceed to the canonical Condition and Skill registries, then implement the deterministic roll-builder evaluator against the completed VAM database. Do not return to hand-coded VAM behavior in the application.
