# Protocol 7 — Resource Authority and Conflict Rules

## Authority order
1. Owner's explicit current instruction.
2. Current canonical rules/data source: `Protocol_7_v0.187_CANONICAL_RULES_SOURCE.json`, or its later owner-approved successor.
3. Latest known-good released/live build of the product being changed.
4. Current workflow, engineering, rulebook, Adventure, and continuity standards.
5. Current release notes, validation, QA, migration, decision, and change records.
6. Historical/development material only for background.

## Conflict rule
Never silently reconcile conflicts. Preserve the higher-authority rule, identify the stale representation, and correct it only when the requested work includes that artifact. A newer version number does not automatically supersede canon.

## Canon gaps
If the canonical source does not answer a new question, do not revive an old discarded rule merely because it exists. Identify the gap. Once the owner makes a decision, record it in canon and the appropriate decision/change record.
