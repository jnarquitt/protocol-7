# Protocol 7 v0.188 — Fast-Track Playtest Release Plan

**Release objective:** Publish a coherent playable v0.188 quickly. Do not delay the playtest for speculative completeness or polishing that can be informed by actual table use.

## Release gate
v0.188 is publishable when all of the following are true:
- one readable player-facing rules product accurately expresses the current rules source;
- the canonical machine-readable rules source agrees with it;
- Skills, VAMs, Gear, Conditions, A/D, Mastery, Vitality, action economy, Reaction, defense, and damage are represented without known contradiction;
- the mobile app can create and run a Level 1 Vector using touch-first controls and current rules;
- the Auditor finds no release-blocking resurrection or cross-product contradiction.

## Explicitly NOT blockers
Do not hold v0.188 for:
- exhaustive Gear balance;
- perfect weapon differentiation;
- a universal critical-hit subsystem;
- Matched Blanks / Dice Tricks;
- exhaustive high-level balance;
- perfect prose or art polish;
- every conceivable historical-era item;
- speculative fixes to mechanics that have not yet caused a playtest problem.

## Execution order
1. **Rules freeze candidate:** current Playtest Rules Source + publication-candidate core JSON + reconciled registries.
2. **Readable rules:** generate v0.188 Interactive Rules Guide/player rulebook from that authority, including the expanded cognitive explanation of dice pools and Vitality.
3. **Mobile app:** synchronize creation, Vitality Ritual, Skills, d12 ceiling, Mastery display, BAR/VAM selection, Gear selection, AP/movement, Reaction, defenses, and touch-first controls. Only Vector name requires typing.
4. **Auditor:** run hard-ass regression review across rules source, JSON, registries, guide, and app. Fix release blockers; log non-blocking concerns for playtest.
5. **Publish:** promote v0.188 as PLAYTEST, update landing page/current links, retain v0.187 as historical predecessor, and record release notes.

## Decision rule
When an unresolved detail is required to make the release playable, make the smallest coherent playtest decision consistent with current design and record it. When it is not required for play, defer it rather than expanding scope.

## Change control until publication
From this point until v0.188 publication, avoid redesigning already coherent systems unless a contradiction, implementation blocker, or obvious mathematical failure is found. New ideas go to the post-release playtest backlog unless they are necessary for basic play.
